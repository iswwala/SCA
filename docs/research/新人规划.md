# 执行规划

## 1. 总体安排

```text
共同背景学习
      ↓
三人独立完成同一个最小实验
      ↓
根据实验结果划分主责方向
      ↓
并行开展不同实验，使用统一设计和报告格式
      ↓
交叉复核
```

每个人都需要：

- 理解 profiling SCA、域适应、GE/key rank 和当前项目主问题；
- 能独立读取数据、运行模型、查看日志和生成评估结果；
- 至少完成一次 Source Only 或等价基线实验；
- 负责一组实验，同时复核另一名成员的实验；
- 提交完整实验报告，而不是只提交代码或截图。

## 2. 共同最小实验

三人首先使用完全相同的实验配置，独立完成一个最小实验 `E0`，使用ASCAD固定密钥集，仅做源域上的模型检验：

```text
ASCAD fixed-key profiling
        → Source Only
        → ASCAD desync50 attack domain
        → 输出 256 类预测概率
        → 计算 key rank / GE
```



### 2.1 E0 的统一配置

- 数据集、源域和目标域
- 轨迹窗口、标签、目标字节和归一化
- backbone、classifier、optimizer 和训练预算
- 评估脚本和 GE 累积方式
- 输出文件格式
- seed：每个人可以使用不同 seed；

### 2.2 E0 的实验报告

提交：

1. 运行命令；
2. 配置文件；
3. 训练日志；
4. prediction 文件或其摘要；
5. GE/key rank 结果；
6. 对代码、数据和指标的问题清单 等等

E0 的目的是确认大家都掌握了完整统一的实验链路。

## 3. 分工原则

完成 E0 后再分配主责方向。主责人负责设计、运行和初步解释，其他成员要能够复现并检查该实验。

| 主责方向             | 主要研究问题                         | 典型实验                                         |
| -------------------- | ------------------------------------ | ------------------------------------------------ |
| 方向 A：方法基线     | 哪些现有域适应方法真正改善迁移？     | Source Only、DANN、CDAN、CDPA/MMD 或 AdaBN       |
| 方向 B：结构与主方法 | 什么 backbone 和 CDAN-SCA 相契合、有效？ | MLP、官方 CNN、ResNet1D、CDAN-SCA full、核心消融 |
| 方向 C：评估与敏感性 | 攻击效果如何测量，方法可靠性如何？     | GE/SR/NTGE 评估、噪声/去同步、攻击预算、样本预算 |

## 4. 轮换式协作

每个主要实验设置一名主责人和一名复核人。主责人先独立完成实验，复核人随后用同一配置复跑关键结果。

| 实验            | 主责人 | 复核人 | 
| --------------- | ------ | ------ | 
| 方法基线实验    | A      | C      | 
| 结构/主方法实验 | B      | C      | 
| 评估/敏感性实验 | C      | A      | 

复核人必须能够使用同一配置重新运行关键步骤，或至少检查原始预测、日志和评估脚本。

## 5. 入门

### 5.1 阶段 A：认识问题

三人共同完成：

- 了解 profiling SCA 的基本流程；
- 了解源域有标签、目标域无标签的域适应设置；
- 了解 AES 中间值、256 类标签和目标字节；
- 了解为什么最终指标是 key rank/GE，而不仅是 accuracy；
- 阅读项目根目录 `README.md`；
- 阅读 `docs/research/datasets_and_links.md`。

### 5.2 阶段 B：认识代码

阅读：

```text
baselines/ascad/ASCAD_OFFICAL/ASCAD/Readme.md  #ASCAD官方，复现此实验可以帮助你快速熟悉项目
```

搞清楚：

- 输入数据是什么；
- 标签在哪里生成；
- 模型输出是什么；
- 预测概率如何变成 key rank；
- 当前src/framework代码还缺少什么。

### 5.3 阶段 C：完成最小共同目标 e0

共同完成：

```text
读取一批数据
→ 运行模型
→ 输出 256 类概率
→ 生成一条正式 GE 或 rank 结果
```

## 6. 分阶段执行计划，仅供参考，具体分工见14节

### 6.1 阶段 1：学习与数据契约

共同任务：

- 熟悉 ASCAD 数据结构和侧信道基本概念；
- 确定一组 source-target 配对：例如ASCAD fixed-key -> desync50；
- 确定 target byte、轨迹长度、样本数量和评估步长；
- 统一 Python 环境和依赖版本；
- 建立实验目录和结果命名规则。

三人分别完成一次数据检查、Source Only 运行和 GE 评估，互相交换结果并检查配置差异。

**阶段验收：** 能够读取真实数据或明确记录数据阻塞；能用小样本生成 prediction 文件和评估结果。

### 6.2 阶段 2：官方模型与 Source Only

任务：

- 运行官方 CNN 或等价 Source Only 模型；
- 使用固定配置和固定 seed；
- 检查源域分类损失是否正常下降；
- 检查目标域预测概率是否有效；
- 生成第一版 GE 曲线；
- 确定所有后续方法共用的 backbone 和 classifier

**阶段验收：** Source Only 结果能够稳定重复。

### 6.3 阶段 3：统一基线

任务：

- 实现或整理 DANN；
- 实现或整理 CDAN；
- 确定 domain loss、gradient reversal 和 conditional representation；
- 记录 domain accuracy、target accuracy、GE 和训练损失；
- 验证所有方法使用相同数据、backbone、训练预算和评估脚本。

三人分别运行至少一个方法；由主责人维护统一 trainer，由另外两人复核数据配置和结果文件。

**阶段验收：** Source Only、DANN、CDAN 可以在同一配置接口下运行。

### 6.4 阶段 4：第一次外层分析

回答：

- DANN 是否降低了域判别准确率；
- 域判别准确率变化是否带来 GE 改善；
- CDAN 是否改善类别结构或 key rank；
- 目标熵是否与预测正确性相关；
- 当前主线应继续做方法创新，还是转向机制诊断。

### 6.5 阶段 5：选择一个创新方向

选择一个方向深入：

**方向 A：校准感知的条件适应**

- 检查熵与正确率的关系；
- 引入温度校准或可靠性权重；
- 对比校准前后的 GE/SR/NTGE。

**方向 B：类别原型保持**

- 计算源域类别原型；
- 对高置信目标样本进行类别结构约束；
- 分析类内距离、类间距离和 GE。

**方向 C：鲁棒性与失效边界**

- 改变目标样本数量、去同步强度或噪声水平；
- 绘制方法有效区间和失败区间；
- 选择一个失败原因进行针对性改进。

选择依据必须来自阶段 4 的结果，不按“哪个模型更复杂”选择。

### 6.6 阶段 6：主实验和消融

任务：

- 运行主方法和关键消融；
- 至少 3 个随机种子；
- 至少 2 个 source-target 配对或 2 种偏移强度；
- 保存全部原始预测和日志；
- 生成主结果表、GE 曲线和消融表。

### 6.7 阶段 7：外部验证

优先选择 CDPA-XMEGA 或 CDPA-SAKURA AES 中的一类数据进行验证。

如果真实 CDPA 数据暂时无法使用，则必须：

- 明确记录数据阻塞原因；
- 将论文表述限制为受控域偏移；
- 不使用“真实跨设备验证已完成”的表述；
- 先完成更多 ASCAD 受控实验和失败分析。

### 6.8 阶段 8：材料与结题

每人提交一部分，最后由三人共同合并：

- 成员 A：数据、域适应基线、实验协议和复现说明；
- 成员 B：结构、主线方法、训练流程和复杂度分析；
- 成员 C：官方攻击基线、鲁棒性结果、指标审计和失败边界。

最终产出：

- 项目报告；
- 代码、配置、日志和结果文件；
- 主结果图表；
- 研究 findings 和后续问题清单。

## 7. 统一实验设计规范

### 7.1 实验期望

实验开始前写出问题：

```text
在固定数据、固定 backbone 和固定训练预算下，改变 X，是否会改善 Y？
```

例如：

```text
在 ASCAD fixed-key → desync50 设置下，加入条件域对齐后，GE 是否优于边缘域对齐？
```

### 7.2 实验设计表

每个正式实验要记录：

| 字段          | 要求                                              |
| ------------- | ------------------------------------------------- |
| 实验编号      | 如`E01`、`E02`，编号不能重复                  |
| 实验名称      | 简洁描述研究对象                                  |
| 研究问题      | 明确要验证什么                                    |
| 研究假设      | 预先写出预期方向，但允许被否定                    |
| 源域/目标域   | 写清数据集、设备、group 和用途                    |
| 数据划分      | profiling、适应、验证、attack evaluation 分开说明 |
| 固定变量      | backbone、标签、目标字节、预处理、optimizer 等    |
| 自变量        | 本轮只改变一个主要因素                            |
| 对比方法      | baseline、proposed、ablation 的角色要分清         |
| 主要指标      | 至少一个 SCA 原生指标，如 GE、SR 或 NTGE          |
| 辅助指标      | accuracy、domain accuracy、entropy、类间距离等    |
| seed 和重复数 | 记录每个 seed；正式结果至少 3 个 seed             |
| 成功判据      | 预先说明什么结果支持假设                          |
| 失败判据      | 预先说明什么结果否定假设或暴露风险                |
| 输出文件      | 日志、配置、预测、模型、表格和图像                |

### 7.3 实验分级

所有实验分为三种级别：

1. **Smoke：** 验证代码、数据接口和输出格式，不作科学结论；
2. **Pilot：** 小规模探索超参数、训练稳定性和方向可行性；
3. **Formal：** 固定协议、多 seed、完整指标，用于论文结果。

实验报告标明级别。

### 7.4 控制变量原则

一轮实验只能改变一个主要因素。例如研究条件域对齐时，不能同时更换：

- backbone；
- 数据预处理；
- 目标字节；
- 训练轮数；
- batch size；
- loss 权重。

如果必须同时改变多个因素，应拆分为多个实验，并说明原因。

### 7.5 推荐实验序列

下面是建议的顺序。

| 编号 | 实验名称               | 核心问题                                   | 主要产出                            |
| ---- | ---------------------- | ------------------------------------------ | ----------------------------------- |
| E0   | 最小端到端实验         | 数据、训练、预测和 GE 链路是否打通？       | prediction、GE/key rank、配置和日志 |
| E1   | Source Only 跨域基线   | 不做适应时，源域模型在目标域下降多少？     | 迁移差距和基线 GE 曲线              |
| E2   | DANN 边缘对齐          | 全局域对齐是否改善目标攻击？               | domain accuracy 与 GE 对照          |
| E3   | CDAN 条件对齐          | 条件对齐是否比边缘对齐更能保持攻击能力？   | Source Only/DANN/CDAN 主比较        |
| E4   | 指标一致性诊断         | accuracy、domain accuracy 和 GE 是否一致？ | 熵、类间距离、域判别和 GE 分析      |
| E5   | 一个 SCA-specific 改进 | 校准或原型约束能否减少错误适应？           | proposed 方法初步结果               |
| E6   | 关键模块消融           | 改进来自哪个模块？                         | 去模块、投影、权重和训练策略消融    |
| E7   | 鲁棒性与失败边界       | 数据量、偏移强度或类别不平衡如何影响方法？ | 敏感性曲线和失败案例                |
| E8   | 真实跨设备验证         | 方法能否从受控偏移迁移到真实设备？         | CDPA 设备结果和结论边界             |

三人完成 E0 后，可以分别主责 E1-E4 中的一组实验， E5-E8 建立在 E1-E4 的结果之上。

### 7.6 每个实验的最低结果要求

不同实验至少要回答的问题：

- **E0：** 能否读取真实数据并生成可解释的预测和排名结果；
- **E1-E3：** 方法是否在同一协议下公平比较；
- **E4：** 域适应指标变化是否与 GE 变化一致；
- **E5：** 改进是否在多个 seed 或多个偏移设置下重复出现；
- **E6：** 性能变化是否能归因于关键模块；
- **E7：** 方法在哪些条件下有效、退化或失败；
- **E8：** 受控数据上的结论能否在真实跨设备数据上成立。

### 8.3 结果解释要求

实验报告必须区分三种内容：

- **事实：** 例如某 seed 的 GE、平均值和标准差；
- **解释：** 例如目标域类间距离降低，可能与负迁移有关；
- **主张：** 例如某方法在当前数据设置下优于 baseline。

解释和主张必须能够追溯到事实，不能只根据一张曲线下结论。

## 9. 每轮工作制度

### 9.1 每轮开始：确定唯一问题

每轮只确定一个主要研究问题，例如：

```text
DANN 降低域判别准确率后，GE 是否一定改善？
```

不要在同一轮同时改变 backbone、损失函数、数据集和训练预算。

### 9.2 过程中：完成最小实验

先运行小数据、少 epoch、单 seed 的验证实验，确认代码逻辑正确，再开始完整实验。只有通过当前阶段验收后，才进入下一阶段。

### 9.3 每轮结束：保存研究证据

每轮必须保存：

- 配置文件；
- 运行命令；
- 训练日志；
- 模型或预测文件；
- 评价结果；
- 一段事实性结论；
- 下一轮实验问题。

## 10. 必须遵守的实验规则

1. 不直接修改历史实验结果；
2. 不把 synthetic smoke 当成真实科学结果；
3. 不用目标标签参与无监督训练或模型选择；
4. 着重检查 GE 或 key rank，这些指标比准确率在此问题中更重要；
5. 不在没有 baseline 的情况下宣称模型有效；
6. 不把多个新模块一次性加入模型；
7. 不删除失败实验，失败结果需要保留并解释；
8. 每次运行都记录 seed、数据量、训练轮数和代码版本；
9. 大型数据、模型和原始轨迹不提交到 Git；
10. 任何论文结论都必须能够追溯到原始结果文件。

## 12. 任务完成评价标准

### 12.1 合格

- 跑通真实数据或明确记录数据阻塞；
- 有一个可复现的 Source Only 基线；
- 有正式 GE 或 key rank 评估；
- 至少完成一种跨域方法或改进路径；
- 至少 3 个 seed；
- 有一份完整实验报告。

### 12.2 良好

- 完成 Source Only、DANN/CDAN 和至少一个强基线比较；
- 完成 2 个以上域偏移或跨设备设置；
- 有消融、敏感性和失败案例；

### 12.3 优秀

- 在真实跨设备数据上完成验证；
- 有明确的 SCA-specific 方法或机制创新；
- 能解释 accuracy、domain accuracy 和 GE 的差异；
- 形成方法、实验、图表和局限性完整的论文材料。

## 13. 文件提交说明

### 13.1 `README.md`

说明本实验的研究问题、数据、方法、运行方式、输出位置和结论边界。任何人只阅读该文件，也应能理解实验为什么做、如何运行以及结果能否用于论文。

### 13.2 `configs/`

保存完整实验配置，至少包括：

- 数据集和源/目标域；
- 数据 group 和目标字节；
- 轨迹长度和预处理；
- 方法名称和模型配置；
- batch size、epoch、learning rate；
- domain loss、lambda、projection dimension 等方法参数；
- seed、样本数量和评估步长。

不允许只在命令行临时输入关键参数而不保存配置。

### 13.3 `scripts/`

保存可重复运行的入口脚本和结果汇总脚本。脚本应支持配置文件或命令行参数，并在输出中记录实际使用的配置。

### 13.4 `reports/`

保存每个实验的完整报告。报告参考第 8 节的模板，不能只写实验结论。

### 13.5 `results/`

保存小型、可提交的结果文件，例如：

- `metrics.csv`：每个 seed、方法和轨迹预算的指标；
- `summary.json`：机器可读的汇总结果；
- `diagnosis.json`：机制分析结果；
- `table_*.csv`：论文表格原始数据。

### 13.6 `figures/`

保存论文或报告中的图表。文件名应包含实验编号，例如 `e02_ge_comparison.png`，不要使用 `final.png`、`new.png` 等无法追踪的名称。

### 13.7 总的`manifests/`

保存运行清单，至少包括：

- 运行命令；
- 运行时间；
- seed；
- 代码版本或 commit；
- 配置文件；
- 输出文件；
- 数据版本或数据哈希；
- 是否为 smoke、pilot 或 formal。

### 13.8 大型文件

以下文件不直接提交到 Git：

- 原始数据集；
- `.h5`、`.npy`、`.npz` 等大数据文件；
- 模型 checkpoint；
- 大型 prediction 文件；
- 重复生成的训练日志压缩包。

大型文件应保存到本地 `outputs/models/<experiment>/` 或 `outputs/results/<experiment>/`，实验目录中的 `manifest.json` 记录其路径、文件大小和哈希。之后统一选择效果较好的方法的数据。

## 14. 研究路线：先复现结构，再开展主线创新

```text
多数据集和多方法基线
        ↓
现有网络结构复现与筛选
        ↓
固定主干网络和实验协议
        ↓
接入当前 CDAN-SCA 主线
        ↓
围绕已观察到的失败机制做一个创新
        ↓
消融、鲁棒性和真实跨设备验证
```

Baselines:

- Source Only
- DANN
- CDAN
- CDPA/MMD
- AdaBN 或其他简单适应方法

Ours:

- CDAN-SCA full

Ablations:

- CDAN-SCA without entropy
- CDAN-SCA without conditional input
- CDAN-SCA with different projection dimensions
- Calibration-aware CDAN-SCA

### 14.1 两个基线角度

#### 14.1.1 方法：回答“域适应方法是否有效”

核心方法固定为：

| 方法           | 作用                         | 是否必须     |
| -------------- | ---------------------------- | ------------ |
| Source Only    | 衡量不做适应时的跨域迁移差距 | 必须         |
| DANN           | 全局边缘域对齐基线           | 必须         |
| CDAN           | 类别条件域对齐基线           | 必须         |
| CDPA/MMD       | 侧信道领域已有的分布对齐基线 | 必须         |
| AdaBN 或 CORAL | 低成本统计对齐基线           | 二选一，可选 |
| Proposed       | 当前项目的主线改进           | 后续完成     |

#### 14.1.2 结构：回答“什么 backbone 适合这个问题”

建议复现：

| 结构                     | 作用                                     | 是否必须         |
| ------------------------ | ---------------------------------------- | ---------------- |
| MLP                      | 非卷积结构参考，检验局部时序建模的必要性 | 必须或低成本参考 |
| ASCAD 官方 CNN           | 官方可复现基线                           | 必须             |
| ResNet1D/MultiResNet     | 残差和多尺度特征参考                     | 必须             |
| CNN + Attention 或 LSTM  | 时序建模扩展                             | 可选             |
| Transformer/复杂混合结构 | 高成本探索                               | 可选             |

结构复现不是单纯报告源域 accuracy。每个结构至少在以下两个层面评价：

- 同域建模能力：源域训练和同域 attack evaluation；
- 跨域迁移能力：ASCAD 受控偏移，最终至少选择一个结构进入 CDPA-XMEGA 验证。

### 14.2 数据集分层和实验范围

为控制组合数量，不做“所有结构 × 所有方法 × 所有数据集”的全组合实验，而采用分层策略。

#### 14.2.1 第一层：结构筛选数据

使用：

```text
ASCAD fixed-key
ASCAD desync50
ASCAD desync100
```

目的：

- 复现 MLP、官方 CNN、ResNet1D/MultiResNet；
- 比较同域性能和受控时序偏移下的 GE；
- 选择一个主干网络，不再让后续方法实验同时变化 backbone。

#### 14.2.2 第二层：方法筛选数据

使用固定的候选主干网络，比较：

```text
Source Only
DANN
CDAN
CDPA/MMD
```

数据包括：

- ASCAD fixed-key -> desync50；
- ASCAD fixed-key -> desync100；
- CDPA Different Implementations 中至少一个受控偏移设置。

目的：判断方法本身效果。

#### 14.2.3 第三层：真实跨设备验证

只把前两层中筛选出的少量组合带入真实数据：

- 首选 CDPA-XMEGA；
- 可选 CDPA-SAKURA AES；
- 再选 XMEGA-EM 或 CHES CTF 2018 作为扩展。

真实跨设备阶段不需要重新运行所有网络结构。建议只比较：

```text
Source Only
最佳传统适应基线
当前主线方法
```

这样能够把工作量控制在合理范围内，同时保留真实设备证据。

### 14.3 可参考以下实验分工

#### 14.3.1 成员 A：方法基线负责人

**定位：** 负责建立“已有方法能否迁移”的基准线，不负责主线创新网络。A 的工作量来自方法数量和数据设置，但必须控制范围，避免跑成全组合。

实验任务：

1. `A-E1`：ASCAD 数据审计、标签和 source/target 划分确认；
2. `A-E2`：ASCAD fixed-key -> desync50/desync100 的 Source Only、DANN、CDAN；
3. `A-E3`：CDPA/MMD 或 AdaBN 二选一，作为简单或领域强基线；
4. `A-E4`：CDPA-XMEGA 上只运行 Source Only、最佳传统基线和最终主线方法；
5. 维护统一的 baseline comparison 表和方法配置。

**得到结论：**

- 不同方法在受控偏移下是否稳定有效；
- CDAN 是否真的优于 DANN；
- CDPA/MMD 或 AdaBN 在真实设备上是否仍然有优势；
- 哪些已有方法适合作为主线比较对象。

#### 14.3.2 成员 B：结构与主方法负责人

**定位：** 负责 backbone 选择、统一 UDA trainer 和 CDAN-SCA 核心实现。B 的任务深度最高，因此减少横向扫参，集中完成主方法和最关键消融。

实验任务：

1. `B-E1`：MLP、官方 CNN、ResNet1D 三种结构同域复现；
2. `B-E2`：三种结构在 ASCAD desync50/desync100 上的迁移比较；
3. `B-E3`：在筛选后的 backbone 上**实现统一 CDAN-SCA trainer**；
4. `B-E4`：运行 CDAN-SCA full 及去掉条件输入、去掉熵权重的消融；
5. `B-E5`：输出主方法配置、模型接口和预测文件，供 A 做真实设备（采集的数据）对比、C 做统一评估

**立即可开始：** B-E1 的同域结构复现。结构复现不依赖 DANN/CDPA 结果。

**主要回答：**

- 哪种结构对时序偏移更稳定；
- 哪种结构适合作为 UDA backbone；
- 条件对齐和熵权重是否分别带来增益；
- 主线创新是否依赖某一特定结构。

#### 14.3.3 成员 C：评估与敏感性负责人

**定位：** C 独立负责一条“统一评估、敏感性和失效边界”实验线；后期再用 A、B 的结果做横向审计。

实验任务：

1. `C-E1`：复现官方 ASCAD CNN 或项目标准监督 CNN，完成同域 GE/key rank 基线；
2. `C-E2`：固定 Source Only 模型，比较 clean、desync50、desync100 和高斯噪声目标域的 GE 曲线；
3. `C-E3`：攻击轨迹预算实验，报告不同攻击轨迹数量下的 GE、SR、NTGE；
4. `C-E4`：目标域样本量敏感性；
5. `C-E5`：选择一个超参数做敏感性，例如投影维度、lambda 或熵阈值；
6. `C-E6`：独立多 seed 复核、domain accuracy/target accuracy/GE 一致性和 confident wrong 分析；
7. `C-E7`：对 A、B 的正式结果进行统一评估脚本复核和失败边界汇总。

**立即可开始：** C-E1、C-E2、C-E3。它们只需要 ASCAD 数据、官方/Source Only 模型和统一 GE 评估脚本，不依赖 A 的 UDA 结果或 B 的创新模型。

**主要回答：**

- 官方 CNN 和 Source Only 的真实攻击基线是什么；
- 去同步和噪声分别造成多大性能下降；
- accuracy、domain accuracy 和 GE 是否一致；
- 目标域样本量与攻击代价之间有什么关系；
- 投影维度、lambda 或熵阈值是否影响结论稳定性；
- 方法在哪些偏移和样本预算下失效。

**C 的产出：** 统一 GE/SR/NTGE 评估脚本、官方基线表、偏移/噪声 GE 曲线、攻击预算曲线、样本预算曲线、一个超参数敏感性表、指标一致性图和失败边界分析。

### 14.3.4 三人并行启动规则

完成共同 `E0` 后，三人立即分别启动以下任务，不设置“C 等 A/B 完成后再开始”的前置条件：

| 成员 | 首批独立任务                                           | 首批交付物                         | 是否依赖其他成员正式结果 |
| ---- | ------------------------------------------------------ | ---------------------------------- | ------------------------ |
| A    | 数据审计、Source Only、DANN 单配对实验                 | 数据契约、基线配置、GE报告         | 否                       |
| B    | MLP、官方 CNN、ResNet1D 的同域复现                     | 结构对比表、训练曲线、模型参数统计 | 否                       |
| C    | 统一 GE 评估脚本、官方 CNN 同域 GE、Source Only 鲁棒性 | 评估脚本、GE 报告、鲁棒性曲线      | 否                       |

后续依赖关系如下：

```text
A：从已有基线扩展到 CDPA/MMD 或 AdaBN，再进入真实设备少量对比
B：从结构筛选扩展到 CDAN-SCA full 和两个核心消融
C：从统一评估扩展到样本预算、超参数敏感性、多 seed 和最终结果审计
```

C 的 `C-E7` 可以使用 A、B 的最终预测文件进行统一复核，但 C-E1 至 C-E6 必须先独立完成，不能把全部工作推迟到最后。

### 14.4 主线前提

主线创新不应在结构复现前开始。至少满足以下条件后再进入：

1. 官方 CNN 或其他参考结构能够稳定完成同域攻击；
2. 至少两种结构已经在 ASCAD 受控偏移下完成比较；
3. Source Only、DANN、CDAN 和 CDPA/MMD 至少在一个统一协议下运行；
4. 已经知道当前主要问题是结构不足、域对齐不足、置信度不可靠还是评价指标不一致；
5. 已经固定主干、数据划分、目标字节和主要训练预算。

### 14.5 必须完成实验

工作量适中的核心集合建议为：

```text
E0：三人独立最小端到端实验
A-E1/A-E2：数据审计、Source Only/DANN/CDAN 基线
A-E3：CDPA/MMD 或 AdaBN 二选一基线
A-E4：CDPA-XMEGA 少量组合的真实跨设备验证
B-E1：MLP、官方 CNN、ResNet1D 结构复现
B-E2：结构在 desync50/desync100 下的迁移比较
B-E3/B-E4：统一 CDAN-SCA trainer、主方法和消融
B-E5：主方法配置、预测文件和接口交付
C-E1：官方 CNN 同域攻击基线
C-E2：desync/高斯噪声鲁棒性
C-E3：攻击轨迹预算和 GE/SR/NTGE
C-E4：目标域样本预算
C-E5：一个超参数敏感性实验
C-E6：多 seed 和指标一致性诊断
C-E7：最终结果复核和失败边界
```

以下内容不纳入核心要求：

- 同时复现 LSTM、Attention、Transformer 等全部结构；
- 在所有数据集上运行所有方法；
- 同时加入校准、原型、注意力、课程学习和 GE loss；
- 一开始就做 ASCADv2 的完整长轨迹多任务实验。

## 15. 文献学习后的实验规范补充

参考文献的详细分析见 [`docs/research/reference_experiment_analysis.md`](reference_experiment_analysis.md)。结合 CDPA、DASA-SCA、CGAN-SCA、DANN 和 CDAN 的实验安排，当前项目补充以下硬性规范：

### 15.1 每个实验必须分开记录四类数据

```text
source_train  -> 源域有标签训练
source_val    -> 源域验证和模型选择
target_adapt  -> 目标域无标签适应
target_attack -> 独立目标域攻击评估
```

`target_adapt` 不能与 `target_attack` 混用。报告中必须说明适应轨迹是否计入攻击成本，并同时保留纯攻击轨迹数和总轨迹数两个结果。

### 15.2 结果优先使用攻击指标

所有主要方法比较至少输出：

- GE 曲线；
- key rank 或达到目标 GE 的轨迹数；
- `N_attack@GE=1`；
- `N_total@GE=1`；
- 多 seed 的均值和波动。

目标域分类准确率、domain accuracy 和 entropy 作为辅助诊断，不能替代密钥恢复结果。

### 15.3 结构筛选和方法筛选分开

先比较 MLP、官方 CNN、ResNet1D/MultiResNet 在同域、desync50 和 desync100 下的表现，再固定一个 backbone 比较 Source Only、DANN、CDAN、CDPA/MMD 和主线方法。不能在结构和域适应方法同时变化时直接宣称某个方法更好。

### 15.4 主线方法必须由失败机制驱动

主线创新需要由前面的实验回答一个明确问题后再确定，例如：

- 域对齐后类别结构仍然混乱；
- 目标域预测置信度不可靠；
- 强去同步下局部特征不稳定；
- 适应样本少时训练不稳定。

消融实验应分别去掉对应机制。
