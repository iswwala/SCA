# 参考文献实验设计学习报告

## 1. 报告目的

本报告针对 `references/papers/ref/` 中的参考论文，重点学习它们如何安排实验，而不是简单复述算法公式。分析内容主要包括：

- 数据集和源域、目标域的组织方式；
- 网络结构和方法基线如何排列；
- 训练、验证、无标签适应和最终攻击数据如何划分；
- 侧信道分析中如何使用 GE、key rank、成功率和所需攻击轨迹数；
- 如何安排消融、敏感性、鲁棒性和失败案例；
- 哪些实验设计可以迁移到当前项目，哪些不能直接照搬。

本报告的结论用于修订当前三人小组的实验分工和论文实验章节规划。

## 3. 文献实验安排的共同结构

几篇文献虽然研究问题不同，但实验结构具有明显的层次性。比较完整的实验通常不是直接运行“提出方法”，而是沿着以下链条展开：

```text
问题和数据定义
    -> 数据集/域偏移说明
    -> 同域或 Source Only 基线
    -> 现有方法比较
    -> 网络结构或训练策略复现
    -> 主方法
    -> 消融和敏感性
    -> 攻击曲线、鲁棒性和失败案例
    -> 计算成本与实际使用代价
```

这说明当前项目应当把“结构复现”和“方法创新”分成两个阶段。否则如果主线方法没有提升，很难判断问题来自域适应方法、backbone、数据预处理还是评估流程。

## 4. CDPA 论文的实验安排

### 4.1 数据域设计

CDPA 的实验设计最适合借鉴。论文没有只使用一个 ASCAD 设置，而是把域偏移拆成多个来源：

1. **跨设备偏移**：使用多块 XMEGA 和 SAKURA 板卡，训练设备和攻击设备不同；
2. **噪声或防护偏移**：在 ASCAD 上构造高斯噪声和时钟抖动目标域；
3. **采集方式偏移**：使用 XMEGA_EM 研究电磁探头位置和采集方式变化；
4. **同一算法在不同实现和设备上的可迁移性**：通过不同平台、不同测量设置形成源域和目标域。

其数据表明确列出每个数据集的：

- 特征数量；
- 训练和验证样本数；
- 无标签 fine-tune 样本数；
- 最终攻击样本数。

这比只写“使用某数据集训练和测试”更适合论文复现，也能避免将适应数据和最终攻击数据混用。

### 4.2 训练阶段和攻击阶段分离

CDPA 将实验划分为两个主要阶段：

```text
源域有标签预训练
    -> 使用源域训练集和验证集训练分类模型
    -> 使用少量无标签目标域轨迹进行域适应/微调
    -> 使用独立目标域攻击集计算 GE
```

论文在 XMEGA 实验中采用了源域训练、源域验证、少量目标域无标签 fine-tune 和目标域攻击集的明确划分；SAKURA_AES 和 ASCAD 也遵循相同思想，只调整样本规模。

当前项目应当保留这种划分，至少在配置和报告中明确写出：

- `source_train`：用于监督训练；
- `source_val`：用于早停或模型选择；
- `target_adapt`：只允许使用无标签目标轨迹；
- `target_attack`：只用于最终 GE/key rank 评估。

### 4.3 先做跨设备矩阵，再做适应结果

CDPA 先报告预训练模型的跨设备攻击矩阵，例如“设备 1 训练、设备 2 攻击”，再报告域适应后的矩阵。这种安排有两个优点：

- 能直接显示跨域问题是否真实存在；
- 能证明提升来自域适应，而不是来自某种数据划分或网络训练偶然性。

当前项目可采用同样的表格形式：

| 源域 | 目标域 | Source Only | DANN | CDAN | CDPA/MMD | 主线方法 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| ASCAD fixed-key | desync50 | GE/NTGE | GE/NTGE | GE/NTGE | GE/NTGE | GE/NTGE |
| ASCAD fixed-key | desync100 | GE/NTGE | GE/NTGE | GE/NTGE | GE/NTGE | GE/NTGE |
| CDPA-XMEGA device A | device B | GE/NTGE | 可选 | 可选 | GE/NTGE | GE/NTGE |

实际报告中不必把所有方法放到所有数据集上，但必须保留“同一数据、同一评估脚本、统一比较”的原则。

### 4.4 攻击成本的处理

CDPA 特别值得借鉴的一点是：用于无监督 fine-tune 的目标域轨迹在实际攻击中也需要采集，因此理论上应计入攻击成本。论文同时给出了不计入 fine-tune 轨迹的主要 `N_TGE`，并明确解释了这一点。

当前项目建议同时报告两种结果：

1. **纯攻击代价**：从 `target_attack` 开始计算达到 GE=1 或 rank=0 所需轨迹数；
2. **总轨迹代价**：`target_adapt` 数量加上达到目标的 `target_attack` 数量。

推荐使用以下命名，避免混淆：

```text
N_attack@GE=1
N_total@GE=1 = N_adapt + N_attack@GE=1
```

如果当前代码暂时只能输出一种结果，也必须在报告中说明是否包含适应样本。

### 4.5 预处理、样本量和适应强度

CDPA 没有把域适应视为唯一因素，还考察了：

- 无预处理、水平缩放、水平标准化；
- 不同源域 profiling 轨迹数量；
- MMD 系数 `lambda` 的敏感性；
- 不同适应层位置；
- 高斯噪声和时钟抖动强度；
- 模型训练和 fine-tune 的计算时间。

这类实验对当前项目的启示是：

- 不能只报告某一个固定超参数下的最好结果；
- 需要区分“数据预处理带来的提升”和“算法本身带来的提升”；
- 域适应样本量应至少做低、中、高三个设置；
- 当目标域偏移增强时，需要报告方法何时失效，而不是只挑选方法有效的设置。

## 5. DASA-SCA 论文的实验安排

### 5.1 结构比较是独立实验主线

DASA-SCA 使用 CNN、ResNet 和 LSTM 作为特征提取网络，并在同一域适应框架中比较它们。论文的关键结论不是某个结构在所有数据上都最好，而是不同数据设置下最优结构可能不同：

- ASCAD fixed-key 的去同步场景中，ResNet 表现较好；
- ASCAD variable-key 的部分场景中，CNN 表现较好；
- 更强的去同步或噪声会改变不同结构之间的相对优势。

这一点直接支持当前项目已经提出的“先复现结构，再进入主线创新”的路线。结构筛选不能只在同域准确率上进行，必须至少包含一个目标域偏移场景。

### 5.2 多种偏移设置

DASA-SCA 在 ASCAD 上构造了：

- `desync50`；
- `desync100`；
- 高斯噪声方差为 2；
- 高斯噪声方差为 4。

同时还把 ASCAD fixed-key 和 variable-key 分开处理，并进一步在 DPA Contest v4.1/v4.2 上测试不同实现和防护设置。

当前项目不必完整复制其全部数据集，但应保留“轻度偏移 + 强偏移”的梯度：

```text
同域
    -> desync50 / 轻度噪声
    -> desync100 / 强噪声
    -> CDPA-XMEGA 真实跨设备
```

这样可以判断某个结构或算法是普遍改善，还是只适合某个偏移强度。

### 5.3 评价指标以攻击结果为核心

DASA-SCA 使用恢复正确密钥所需的轨迹数作为主要比较结果，并辅以 key rank/GE 曲线，而不是把分类准确率作为最终结论。

当前项目应当采用相同的优先级：

1. 首要结果：GE 曲线、达到指定 GE 的轨迹数、最终 key rank；
2. 辅助结果：攻击成功率、目标域分类准确率、预测熵；
3. 机制结果：域分类准确率、特征分布、类内和类间距离。

目标域准确率可以帮助定位问题，但不能替代密钥恢复指标。

## 6. CGAN-SCA 论文的实验安排

### 6.1 多数据集和跨实现验证

CGAN-SCA 使用 ASCADr、ASCADf、DPA v4.2、CHES CTF 2018 和 ESHARD-AES128 等多个公开数据集，重点考察不同平台、指令集、采样方式和防护实现之间的迁移。

它的实验设计说明：如果论文声称方法具有跨实现能力，仅在 ASCAD fixed-key 和 desync 数据上验证是不够的。至少需要一个不同设备或不同实现的数据集作为外部验证。

对当前项目而言，合理的规模是：

- 主实验：ASCAD fixed-key 的受控域偏移；
- 外部验证：CDPA-XMEGA；
- 扩展验证：CDPA-SAKURA_AES、XMEGA_EM 或其他可获得数据集中的一个。

不建议一开始同时覆盖 CGAN-SCA 的全部数据集，因为数据预处理和实验成本会明显增加。

### 6.2 使用下游攻击指标选择模型

CGAN-SCA 没有用 GAN loss 直接决定最优生成器，而是在每个搜索结果上进行下游 profiling attack，并以验证集达到 GE=1 所需的轨迹数作为选择依据。

这对当前项目有很强的启发：

- 训练损失下降不等于攻击效果变好；
- domain loss 变小不等于密钥恢复更好；
- 模型选择应尽可能依据独立验证集上的 GE、key rank 或攻击成功率；
- 训练日志中应同时保存分类损失、域损失、适应损失和攻击指标。

当前项目不必复制其大规模随机超参数搜索，但可以采用较小的、可解释的选择策略：

```text
先固定主干和数据划分
    -> 在源域验证集上确定基本训练设置
    -> 用目标域无标签数据完成适应
    -> 用独立目标攻击集计算 GE
    -> 只在预先规定的候选配置中选择
```

不能使用最终攻击集上的结果反复挑选超参数，否则会把测试集变成验证集。

### 6.3 丰富的基线

CGAN-SCA 同时比较了：

- 提出的方法；
- 黑盒深度学习 profiling；
- 白盒深度学习 profiling；
- Gaussian Template Attack；
- PCA/LDA 等传统方法或降维方法。

当前项目不需要照搬其白盒威胁模型，因为当前主线是无监督域适应，但可以保留以下思想：

- 至少有 Source Only 作为黑盒深度学习基线；
- 至少有 DANN、CDAN、CDPA/MMD 等已有适应方法；
- 可以加入一个简单传统基线或浅层模型，验证提升不是来自评估实现错误；
- 如果报告声称“实用性”，需要报告方法的额外数据、训练时间和推理成本。

## 7. DANN 和 CDAN 论文可迁移的实验逻辑

DANN 和 CDAN 是通用域适应论文，其图像分类数据集和准确率指标不能直接复制到侧信道分析。但它们的实验组织方式适合借鉴。

### 7.1 方法矩阵

通用域适应论文通常至少包含：

```text
Source Only
    -> DANN
    -> CDAN
    -> CDAN+E 或其他条件/熵增强变体
    -> 当前主线方法
```

当前项目中可以将其转换为：

```text
Source Only
    -> DANN
    -> CDAN
    -> CDAN + entropy conditioning（若代码和任务定义允许）
    -> CDPA/MMD
    -> 当前主线方法
```

所有方法必须共享：

- 相同的源域和目标域；
- 相同的标签和目标字节；
- 相同的 backbone；
- 相同的训练/验证/适应/攻击划分；
- 相同的 GE 和 key rank 评估脚本。

### 7.2 消融不能只删掉一个网络模块

CDAN 论文对条件信息、熵条件和随机多线性映射做了变体比较。这提示当前项目的消融应当围绕“假设”设计，而不是机械地删层：

- 去掉域适应损失；
- 去掉条件信息，仅保留域对抗；
- 去掉熵或置信度加权；
- 去掉类别原型/结构保持项；
- 改变适应层位置；
- 改变目标域无标签样本量。

每一个消融都需要回答一个明确问题，并使用与主实验相同的随机种子和评估预算。

## 8. 文献实验设计中不能直接照搬的部分

### 8.1 不同威胁模型不能混合

CGAN-SCA 使用参考实现、profiling 实现和目标实现，部分实验还使用了白盒 mask 信息进行分析。当前项目的主线是源域有标签、目标域无标签的 UDA 设置，因此不能把目标域标签、mask 或最终攻击集标签用于模型选择。

### 8.2 分类准确率不是 SCA 的最终指标

DANN/CDAN 的主要结果是分类准确率，但当前项目必须将 GE/key rank 放在首位。目标域准确率只能作为诊断指标，不能单独用来证明密钥恢复能力。

### 8.3 不能把所有数据集和模型一次性全部复现

文献往往由成熟研究团队完成，数据集、算力和实验基础都比当前本科生小组充足。当前项目应采用“核心集合 + 扩展集合”：

- 核心集合保证可完成、可复核、可写入论文；
- 扩展集合只在核心结论稳定后加入。

### 8.4 最好结果不能替代多次运行

部分短篇论文展示了代表性结果，但当前项目若要形成高质量论文，至少应对最终候选方法和关键基线进行多 seed 运行，报告均值、标准差或置信区间，并保留失败运行记录。

## 9. 对当前项目的直接实验建议

### 9.1 实验层次

建议最终采用四层结构：

#### 第一层：流程和同域正确性

- ASCAD fixed-key -> ASCAD fixed-key；
- Source Only；
- 验证数据读取、标签、预测概率、GE/key rank；
- MLP、官方 CNN、ResNet1D 至少完成一次同域对比。

#### 第二层：受控域偏移

- ASCAD fixed-key -> desync50；
- ASCAD fixed-key -> desync100；
- 可选加入高斯噪声低强度和高强度；
- 比较 Source Only、DANN、CDAN、CDPA/MMD 和主线方法。

#### 第三层：真实跨设备或跨采集设置

- 首选 CDPA-XMEGA；
- 只带入 Source Only、最佳传统适应基线和主线方法；
- 记录目标域无标签适应轨迹数；
- 同时报告纯攻击代价和总轨迹代价。

#### 第四层：机制、鲁棒性和失效边界

- 目标域样本量敏感性；
- 适应系数敏感性；
- 结构与适应层消融；
- GE、domain accuracy、entropy 和 target accuracy 的一致性；
- 负迁移和失败案例；
- 最终方法的多 seed 复核。

### 9.2 推荐的最小方法矩阵

| 类别 | 方法 | 是否核心 | 作用 |
| --- | --- | --- | --- |
| 无适应基线 | Source Only | 必须 | 确定域偏移造成的性能下降 |
| 对抗适应 | DANN | 必须 | 观察普通域对抗的效果 |
| 条件对抗 | CDAN | 必须 | 验证类别条件信息是否有帮助 |
| 分布对齐 | CDPA/MMD | 必须 | 参考跨设备侧信道研究中的方法 |
| 简单预处理/浅层模型 | 传统或轻量基线 | 建议 | 排除评估和数据流程问题 |
| 当前主线方法 | 项目提出的方法 | 必须 | 在已有失败机制上提出针对性改进 |

### 9.3 推荐的最小结构矩阵

| 结构 | 作用 | 进入条件 |
| --- | --- | --- |
| MLP | 最简单的非卷积参考 | 作为轻量结构或流程基线 |
| 官方 ASCAD CNN | 与已有侧信道实验对齐 | 必须稳定运行 |
| ResNet1D/MultiResNet | 检验残差和多尺度特征 | 核心结构复现 |
| LSTM 或轻量注意力 | 检验时序建模方向 | 资源允许时扩展 |
| Transformer | 参数和训练成本较高 | 不列入本科生核心要求 |

结构筛选阶段只比较已有结构，不要同时引入多个新模块。主线创新应在固定 backbone 后进行。

## 10. 统一实验报告要求

每个实验报告至少应包含以下内容：

1. **研究问题**：本实验要验证什么假设；
2. **数据域定义**：源域、目标域、偏移来源和数据文件；
3. **数据划分**：source train、source val、target adapt、target attack；
4. **标签和泄漏模型**：目标字节、标签生成方式、类别数；
5. **模型和训练设置**：backbone、损失、优化器、学习率、batch size、epoch、seed；
6. **适应信息**：是否使用目标域无标签数据、数量是多少、是否计入总攻击成本；
7. **主要指标**：GE 曲线、key rank、`N_attack@GE=1`、`N_total@GE=1`；
8. **辅助指标**：accuracy、domain accuracy、entropy、训练损失和适应损失；
9. **多次运行**：seed、均值、标准差或失败次数；
10. **结论边界**：在哪些设置有效，在哪些设置无效；
11. **可复现信息**：配置文件、命令、结果清单、代码提交版本。

报告不能只放一张 GE 图。至少需要一张结果表、一张关键曲线和一段对失败或异常结果的解释。

## 13. 最终结论

参考文献给出的最重要经验不是“选择某一个更复杂的网络”，而是建立一条可信的实验证据链：

```text
同域流程正确
    -> 现有结构可复现
    -> 域偏移确实造成困难
    -> 多种已有方法公平比较
    -> 主线方法针对明确失败机制改进
    -> GE/key rank 和攻击成本改善
    -> 多 seed、跨偏移、真实设备验证
```

因此，当前项目的实验路线应当维持“先基线和结构复现，后主线创新”的安排。ASCAD 适合用于控制变量和快速迭代，CDPA-XMEGA 适合用于真实跨设备验证；两者承担不同作用，不能互相替代。

当前最值得保留、且能直接服务论文的实验组合为：

```text
MLP/CNN/ResNet 结构复现
    + Source Only/DANN/CDAN/CDPA 方法矩阵
    + ASCAD desync50/desync100 受控偏移
    + 目标无标签样本预算敏感性
    + GE/key rank/总攻击轨迹成本
    + CDPA-XMEGA 真实跨设备验证
    + 一个针对失败机制的主线创新及消融
```

这套组合的工作量足以支撑三人并行开展实验，也能为当前项目论文提供相对完整的实验章节，而不是停留在单数据集、单模型和单次运行的复现实验。
