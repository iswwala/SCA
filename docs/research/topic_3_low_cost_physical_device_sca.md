# 基于低成本微控制器实测功耗轨迹的侧信道分析与跨设备迁移研究

## 一、课题简介

侧信道分析通常使用密码设备运行时产生的功耗、电磁辐射或时间变化，推断其内部处理的中间数据和秘密密钥。与只在公开数据集上训练模型相比，直接从真实微控制器采集功耗轨迹，能够检验算法是否真正适用于实际物理设备。

本课题面向一个低成本、可重复搭建的微控制器实验平台，在自有设备上实现一个简单的 AES-128 软件程序，采集设备执行加密过程时的功耗轨迹，并研究当前学界提出的机器学习模型在真实轨迹上的建模攻击效果。完成单设备采集和攻击后，再将两块或多块同型号设备、不同固件配置或外部目标板作为扩展，研究真实设备差异对模型迁移的影响。

本课题的核心问题是：

> 在低成本实验条件下，能否建立稳定的真实功耗轨迹采集流程，并验证深度学习侧信道分析方法在真实微控制器和跨设备场景中的有效性、局限性与改进空间？

## 二、为什么需要真实物理设备实验

公开侧信道数据集适合算法比较，但它们通常已经完成了采集、裁剪、格式化和标签整理。研究者可以直接得到固定长度的轨迹和标签，却不一定能观察到真实测量中的问题，例如：

- 触发时刻不稳定；
- 采样率和时间窗口选择不合适；
- 电源、USB、示波器和主板之间存在干扰；
- 同一算法在不同芯片上的波形幅值和泄露位置不同；
- 设备运行状态、编译参数和时钟设置会改变轨迹形态；
- 公开数据上的分类提升不能直接转化为真实密钥恢复提升。

因此，真实物理设备实验可以补充公开数据集无法提供的证据：

1. 验证采集、预处理、训练和攻击评价是否能够形成完整闭环；
2. 观察真实硬件噪声和设备差异对模型的影响；
3. 检验公开数据上得到的特征或域适应方法能否迁移到真实轨迹；
4. 为论文增加现实应用验证，而不仅是受控数据集上的结果。

## 三、建议的低成本实验平台

本课题不要求搭建复杂密码硬件或购买高端示波器。建议采用“低成本目标板 + 简单测量链路 + 可选共享采集设备”的分层方案。

### 1. 首选入门平台：ChipWhisperer-Nano

如果学校能够提供一台共享设备，建议优先使用 ChipWhisperer-Nano 完成第一阶段。官方文档将其定位为面向训练和教学的低成本侧信道功耗分析平台，内置 STM32F030 目标、基本触发和采集接口，ADC 最高采样率为 20 MS/s，采样缓存为 50,000 点。它可以减少学生自行处理触发、模拟前端和采样同步的工作量，适合先完成“固件—采集—数据保存—模型—GE”闭环。

ChipWhisperer-Nano 的定位是入门和教学平台，采集能力低于 ChipWhisperer-Lite 或更高端设备。因此，本课题不把它作为高精度测量工具，而是把它作为低成本真实设备验证平台。第一阶段只要求在其内置 STM32F030 上完成一个可复现的 AES-128 实验。

### 2. 低成本外部目标设备：Raspberry Pi Pico / RP2040

如果需要增加外部目标设备，Raspberry Pi Pico 是一个合适的低成本选择。它基于 RP2040，官方规格包括双核 Cortex-M0+、最高 133 MHz 主频、USB、GPIO 和可编程 I/O 等资源，适合编写固定接口的 AES-128 软件程序和输出触发信号。官方页面将 Pico 1 系列标为可从 4 美元起的低成本开发板。

建议准备 2 至 3 块同型号 Pico，用于：

- 第一阶段：单板采集和端到端流程验证；
- 第二阶段：两块板分别作为源设备和目标设备；
- 第三阶段：不同编译选项、时钟设置或供电条件下的受控变化。

### 3. 可替代目标设备：低成本 STM32 或 AVR 开发板

如果实验室已有 STM32F103、STM32F0、Arduino Nano 或其他带有稳定串口和 GPIO 的微控制器，也可以作为外部目标设备。Arduino Nano 的 ATmega328 平台结构简单、资料丰富，适合教学入门；STM32 平台则更接近许多公开侧信道实验中常见的 Cortex-M 设备。

目标设备的选择原则是：

- 能够运行可控的 AES-128 软件实现；
- 能够通过串口接收明文和密钥，或使用固定测试向量；
- 能够输出稳定的 GPIO trigger；
- 能够独立供电，并在电源路径中串入测量电阻；
- 至少可以重复执行数千次相同接口的加密操作。

### 4. 基础采集链路

最低限度的采集链路包括：

- 微控制器开发板；
- AES-128 软件实现和测试固件；
- 触发 GPIO；
- 示波器或具有模拟采集能力的 USB 采集设备；
- 稳定的 3.3 V 或 5 V 供电；
- 上位机采集脚本、串口控制脚本和数据保存程序。

如果学校已有 ChipWhisperer-Lite，可以将其作为更稳定的共享采集设备。官方文档说明 Lite 由功耗分析采集仪和目标板组成，适合将 AES 固件加载到目标板后执行功耗分析。它不是本课题的硬性购买要求；ChipWhisperer-Nano、学校已有示波器或其他合适的模拟采集设备都可以完成基础研究。

如果预算非常有限，可以先使用一台共享的 ChipWhisperer-Nano 完成“真实轨迹采集 + 单设备建模攻击”。只有在单设备流程稳定后，再增加第二块同型号设备开展跨设备迁移。

## 四、数据采集与标签设计

### 1. 固定实验任务

建议先实现 AES-128 的一个固定字节分析任务：

- 每次加密使用已知明文和固定或可控密钥；
- 通过 trigger 标记目标 AES 操作的起止区间；
- 采集目标操作期间的功耗轨迹；
- 根据明文和密钥计算目标 AES 中间值标签；
- 训练阶段使用源设备标签；
- 目标设备标签只用于离线评估，模拟真实无标签目标域。

### 2. 推荐数据规模

第一阶段不追求一次采集几十万条轨迹，建议分层完成：

- 流程验证：每块设备 500 至 2,000 条轨迹；
- 初步建模：每块设备 5,000 至 20,000 条轨迹；
- 稳定性实验：每块设备至少重复两次采集，或使用 2 至 3 块同型号设备；
- 最终论文实验：根据采集质量和模型训练成本确定，不以轨迹数量本身作为贡献。

如果真实轨迹噪声较大，应优先改善触发、供电、窗口和采样质量，而不是盲目增加数据量。

### 3. 数据格式

建议将每次采集保存为统一记录：

```text
trace:       [T] float32
plaintext:   [16] uint8
key:         [16] uint8, training metadata only
label:       uint8, target intermediate value
device_id:   string
firmware_id: string
clock:       integer
trigger_id:  integer
```

目标域训练文件中应去掉或隐藏 `key` 和 `label`，只在最终评估脚本中读取真实标签。这样可以避免无意中使用目标域标签，保证实验符合无监督域适应设定。

### 4. 从真实采集文件到机器学习数据集

真实采集数据不能直接送入模型，需要经过一个可重复的数据转换流程。建议将原始数据、处理后数据和评估标签分开保存，避免后续实验无法追溯。

#### 第一步：保存原始采集记录

每次采集完成后，先保存未经裁剪和归一化的原始轨迹，以及采集时的控制信息：

```text
raw/
  batch_001/
    traces.npy                 # [N, T_raw]
    plaintext.npy              # [N, 16]
    key.npy                    # [16]，仅限受控实验保存
    capture_meta.json          # 采样率、设备、时钟、触发和日期
```

原始文件不应被后处理脚本覆盖。若某批数据存在异常，应通过新的处理配置生成新版本，而不是直接修改原始轨迹。

#### 第二步：数据质量检查

对每一批轨迹执行自动检查，并输出质量报告：

- 轨迹长度是否一致；
- 是否存在全零、饱和、截断或 NaN 轨迹；
- 触发位置是否落在预期范围；
- 峰值、均值、方差和能量是否存在明显异常；
- 相邻轨迹是否出现重复采集或串口错位；
- 明文、轨迹和设备编号的行数是否一一对应。

异常轨迹可以被标记为 `invalid`，但不能静默删除。报告中应记录删除数量、删除规则和每个批次的有效率。

#### 第三步：裁剪、对齐和预处理

根据 trigger 或预先定义的时间窗口，从 `T_raw` 个采样点中裁剪长度为 `T` 的模型输入。可比较以下处理方式：

- 不做对齐，只使用固定触发窗口；
- 基于触发位置的平移对齐；
- 轻量滤波或去基线；
- 每条轨迹归一化；
- 使用源域统计量进行跨域归一化。

预处理参数必须在训练前固定。若采用均值、标准差或滤波参数，默认只能使用源域训练集估计，不能使用目标域标签，也不应使用目标域攻击集的统计信息来选择最优方案。不同预处理方式应作为独立实验配置保存。

#### 第四步：生成泄露标签和密钥评估信息

根据每条轨迹对应的明文、密钥和 AES S-box 计算目标中间值。例如，对目标字节 `b`，可以定义：

```text
v_i = SBox(plaintext_i[b] XOR key[b])
```

其中 `v_i` 是用于 256 类分类的标签，范围为 `0` 到 `255`。如果研究其他泄露模型，例如汉明重量，应另外生成标签并在配置中明确记录，不能与中间值标签混用。

密钥和明文还要保留在独立的评估元数据中，用于之后将模型输出的 256 类概率转换为 256 个密钥候选的对数似然，并计算 GE、key rank、SR 和 NTGE。模型训练不应直接读取目标域的真实密钥标签。

#### 第五步：划分源域、目标域和评估集

转换脚本应输出至少三类文件：

```text
processed/
  source_train.npz       # x: [N_s, T, 1], y: [N_s]
  source_valid.npz       # x: [N_v, T, 1], y: [N_v]
  target_adapt.npz       # x: [N_t, T, 1]，训练时不提供 y
  target_attack.npz      # x: [N_a, T, 1]，用于最终预测
  target_eval_meta.npz   # plaintext、key 和设备信息，仅供评估
  manifest.json          # 数据版本、处理参数和样本统计
```

在无监督域适应实验中：

- `source_train` 提供轨迹和标签；
- `source_valid` 用于源域模型选择和训练监控；
- `target_adapt` 只提供轨迹，不提供标签；
- `target_attack` 用于产生预测概率；
- `target_eval_meta` 只在离线评估阶段参与密钥排名计算。

如果进行纯跨设备测试，也可以不使用 `target_adapt`，直接把目标设备作为完全未参与训练的攻击集。两种设定应分别报告。

#### 第六步：转换为模型输入张量

最终交给 TensorFlow 或 PyTorch 的输入应满足：

```text
X.shape = [number_of_traces, trace_length, 1]
y.shape = [number_of_traces]
y.dtype = int64 or int32
X.dtype = float32
```

其中最后一个维度表示单通道功耗信号。数据加载器还需要提供：

- batch 采样；
- 源域有标签 batch；
- 目标域无标签 batch；
- 固定随机种子；
- 每次运行的数据 manifest 和样本数量记录。

#### 第七步：模型输出与攻击评价

模型对每条目标轨迹输出 `N x 256` 的概率矩阵：

```text
predictions.shape = [number_of_attack_traces, 256]
```

随后使用目标攻击集的明文、真实密钥和 AES S-box，将类别概率映射到 256 个密钥候选，按轨迹累积对数概率，得到 GE/key-rank 曲线。这样才能把“模型完成了 256 类分类”转化为“真实密钥需要多少条轨迹才能恢复”的侧信道结论。

### 5. 建议新增的数据转换工具

为保证真实采集数据能够被现有和后续模型复用，建议实现一个独立的数据转换入口，例如：

```text
experiments/real-device-sca/scripts/prepare_dataset.py
```

该脚本至少应支持：

- 输入原始轨迹和采集元数据；
- 根据配置裁剪、对齐和归一化；
- 生成中间值或其他泄露模型标签；
- 按设备和实验批次划分数据；
- 输出 `.npz` 或 HDF5 数据集；
- 生成 `manifest.json` 和质量报告；
- 明确隐藏目标域标签；
- 保存处理配置和数据版本。

这部分不是简单的数据格式转换，而是连接“物理采集”和“机器学习验证”的关键工程环节。没有它，真实采集的轨迹只能作为原始记录，无法稳定地用于比较不同模型或复现实验。

### 6. 使用 ASCAD 官方基础 CNN 作为第一验收算法

为了让真实采集课题有一个清晰、可重复、不过度依赖新算法的起点，第一阶段应使用 ASCAD 官方代码中的基础 `cnn` 模型进行测试。该模型不是本课题的创新方法，而是用于验收“真实采集数据能否被整理成可用于机器学习和密钥恢复的数据集”。

官方基础 CNN 的主要配置为：

- 输入：长度为 `T` 的单通道轨迹，模型输入形状为 `[N, T, 1]`；
- 输出：256 类 AES 中间值概率，输出形状为 `[N, 256]`；
- 网络：5 个一维卷积与平均池化模块，卷积通道数依次为 64、128、256、512、512；
- 卷积核：默认宽度为 11；
- 分类头：Flatten 后连接两个 4096 单元全连接层和 256 类 softmax；
- 损失：多类交叉熵；
- 优化器：RMSprop，官方示例学习率为 `1e-5`；
- 训练：先使用固定的 batch size、epoch、验证比例和早停规则，避免在第一阶段进行复杂调参。

真实采集轨迹的长度可以通过裁剪窗口配置为 `T`，但必须在数据 manifest 中记录窗口起点、窗口长度和采样率。若真实轨迹长度与官方示例不同，应保持网络结构和训练目标不变，只调整输入长度，不能同时修改多个模型组件。

#### 第一阶段的明确目标

第一阶段只回答一个问题：

> 从真实微控制器采集的功耗轨迹，经过数据检查、裁剪、标签生成和格式转换后，能否被 ASCAD 官方基础 CNN 正确训练，并通过真实密钥排名评价形成完整攻击闭环？

#### 必须完成的验证

1. **输入验证**：能够生成 `X.shape = [N, T, 1]`、`y.shape = [N]` 的训练数据，数据类型和标签范围正确；
2. **训练验证**：官方 CNN 能够正常训练，训练损失、验证损失和预测概率能够保存；
3. **输出验证**：目标攻击集能够生成 `[N_attack, 256]` 的概率矩阵；
4. **密钥评价验证**：能够根据明文、目标字节和密钥元数据计算 GE、key rank、SR 和 NTGE；
5. **重复性验证**：相同数据划分和配置至少运行 3 个随机种子，并保存逐 seed 结果；
6. **负对照验证**：至少增加一种标签打乱或明文/标签错配对照，证明模型性能不是由数据索引错误或评估泄漏造成的。

#### 第一阶段的通过标准

不要求第一次真实采集就达到公开 ASCAD 数据集的攻击效果，也不预设必须在固定轨迹数内恢复密钥。建议使用以下标准判断数据链路是否基本通过：

- 训练、预测和 GE 评估全流程可以无人工改文件地运行；
- 有效轨迹、标签、明文和元数据能够一一对应；
- 正确标签实验的目标 rank 曲线总体优于随机或标签打乱对照；
- 随着攻击轨迹数量增加，正确标签实验的密钥排名具有可重复的下降趋势；
- 3 个随机种子的结果方向基本一致，若波动很大，必须先分析采集质量和数据划分；
- 所有删除的异常轨迹、预处理参数和评估配置都能从 manifest 和日志中追溯。

如果正确标签实验无法明显优于标签打乱对照，优先判断为采集链路、触发同步、标签生成、目标窗口或数据格式问题，而不是立即更换复杂模型。

#### 官方 CNN 基线实验输出

第一阶段至少应生成以下文件：

```text
real-device-sca/
  configs/official_cnn_real_device.json
  processed/manifest.json
  reports/data_quality.json
  results/official_cnn_seed42/history.json
  results/official_cnn_seed42/predictions.npy
  results/official_cnn_seed42/ge_curve.csv
  results/official_cnn_seed42/summary.json
  results/official_cnn_comparison.csv
```

其中 `official_cnn_comparison.csv` 至少包含正确标签、标签打乱对照和必要的公开数据对照，字段包括训练样本数、目标准确率、最终 GE、NTGE、SR 和运行时间。该表可以作为后续复杂算法、跨设备迁移和真实环境改进的统一基线。

#### 第二阶段才进行算法改进

只有官方 CNN 在真实数据上完成上述闭环后，才进入以下研究：

- 改进预处理或时序对齐；
- 更换或增强特征表示；
- 加入域适应或跨设备训练；
- 研究目标域无标签数据的利用；
- 比较不同模型在真实设备上的迁移效果。

这样可以明确区分：

- 官方 CNN 负责证明真实数据链路和基础攻击是可行的；
- 后续方法负责研究真实环境中的性能提升、跨设备迁移或失效原因。

## 五、拟解决的科学问题

本课题重点是让真实设备数据反过来检验已有方法和提出新的研究问题：

1. 低成本采集链路能否稳定获得包含 AES 泄露信息的功耗轨迹？
2. 在真实轨迹上，分类准确率和密钥恢复指标是否仍然一致？
3. 公开 ASCAD 或其他数据集上学习的特征，能否迁移到自采集轨迹？
4. 两块同型号设备之间的差异是否足以造成明显的目标域性能下降？
5. 采集噪声、触发偏移、时钟变化和供电变化分别对模型造成什么影响？
6. 数据预处理、结构设计、域适应或训练策略中，哪一类改进最能提高真实设备攻击效率？
7. 一个在模拟去同步数据上有效的方法，是否也能在真实设备差异下保持有效？

## 六、研究内容与开放技术路线

### 1. 真实采集系统搭建

- 编写或移植适合微控制器的 AES-128 测试固件；
- 设计明文输入、串口控制、触发信号和采集协议；
- 完成供电、分流电阻、示波器和目标板连接；
- 记录采样率、带宽、触发位置、时钟和编译参数；
- 设计数据完整性检查和重复采集检查。

### 2. 真实轨迹质量分析

- 观察不同明文、不同设备和不同采集批次的波形差异；
- 检查触发抖动、基线漂移、幅值变化和异常轨迹；
- 研究裁剪、对齐、归一化、滤波或其他预处理的影响；
- 区分“真实泄露不足”和“采集链路不稳定”两类问题。

### 3. 建模侧信道攻击验证

- 在真实单设备数据上完成 profiling 攻击；
- 以真实密钥排名、GE、SR 和 NTGE 作为核心评价；
- 与公开数据集上的结果进行对比，但不直接混合平均；
- 研究模型规模、轨迹数量和噪声水平对攻击效果的影响。

### 4. 跨设备与跨条件实验

在单设备流程稳定后，可以逐步增加：

- 源板训练、目标板无标签适应；
- 不同芯片或不同开发板之间的迁移；
- 不同编译选项、主频或供电条件；
- 不同触发位置、窗口和采样配置；
- 公开数据到实测数据的迁移；
- 实测数据到实测数据的跨设备泛化。

技术路线可以从预处理、特征表示、监督学习、域适应、伪标签、数据增强或其他方法中选择。题目本身不预设哪一种方法一定有效，重点是通过真实实验判断方法的适用性。

### 5. 真实设备上的改进与验证

小组应从前期采集结果中选择一个主要瓶颈进行改进，例如：

- 触发和时序不稳定；
- 不同设备的幅值和波形差异；
- 真实噪声导致的错误高置信预测；
- 公开数据与实测数据之间的特征差异；
- 训练指标与密钥恢复指标不一致。

改进可以是算法、网络、数据处理或采集协议，但必须说明改进针对的真实问题，并用控制变量实验验证。

## 七、三人小组分工建议

### 第一人：嵌入式固件与物理采集

- AES 测试固件、串口协议和 trigger 设计；
- 目标板供电和测量连接；
- 示波器或采集设备控制；
- 采样率、窗口、同步和数据质量记录。

### 第二人：数据处理与机器学习模型

- 轨迹格式、标签生成和数据分割；
- 预处理、特征表示和候选模型；
- 训练、模型保存和预测概率导出；
- 单设备和跨设备训练流程。

### 第三人：攻击评价与实验分析

- 多设备、多批次汇总；
- 真实设备与公开数据的对比；
- 噪声、同步、采样和模型失效分析；
- 论文图表和实验结论整理。

## 八、预期成果

### 课题成果

- 一套低成本微控制器侧信道采集平台；
- 一份硬件连接、固件、采集参数和数据格式说明；
- 一套真实功耗轨迹数据及元数据；
- 单设备 profiling SCA 实验结果；
- 至少一种跨设备或跨采集条件实验；
- 真实设备上的 GE、key rank、SR 和 NTGE 结果；
- 预处理、结构或训练路径的改进实验；
- 可复用的采集脚本、数据处理脚本和攻击评价代码。

### （可用于主论文的成果）

该课题可以为主论文提供独立的真实设备验证部分：

- **Real-Device Evaluation**：真实微控制器上的功耗轨迹攻击结果；
- **Physical Measurement Protocol**：采集、触发、同步和数据契约；
- **Cross-Device Validation**：两块或多块设备之间的迁移结果；
- **Reality Gap Analysis**：公开/模拟数据与真实轨迹之间的差异；
- **Robustness and Failure Analysis**：真实噪声、时序和设备变化下的方法边界；
- **Practicality Discussion**：采集成本、数据量、训练时间和部署限制。

如果真实设备实验没有得到理想的攻击效果，也可以形成重要结论：算法在公开数据上的提升是否能够转化为物理设备收益，以及失败主要来自采集系统、数据规模还是模型迁移问题。

## 九、建议的分阶段计划

### 阶段一：单板采集闭环

- 选择一种低成本微控制器；
- 完成 AES 固件和 trigger；
- 用少量轨迹确认波形、标签和数据保存正确；
- 完成单设备模型训练和 GE 评估。

### 阶段二：真实数据质量与算法基线

- 增加采集规模；
- 完成预处理对比；
- 比较至少两种基础建模路径；
- 确定真实数据上的主要瓶颈。

### 阶段三：跨设备或跨条件验证

- 增加第二块同型号设备，或改变固件/时钟/供电条件；
- 构造源域和目标域；
- 目标域训练只使用无标签轨迹；
- 报告跨设备 GE、SR 和 NTGE。

### 阶段四：针对性改进与论文材料

- 针对一个物理或算法瓶颈选择改进路径；
- 完成消融、多批次和多 seed 实验；
- 整理真实设备结构图、采集流程图、波形图和 GE 曲线；
- 撰写真实设备验证、局限性和适用范围。

## 十、主要风险与止损方案

### 风险一：采不到稳定的泄露轨迹

先将研究目标降为“采集链路验证 + 数据质量诊断”，使用公开 ASCAD 或 CDPA 数据完成算法部分；不应在采集质量未确认前直接运行大规模模型。

### 风险二：只有一块设备，无法完成真实跨设备实验

先完成单设备 profiling SCA，再通过第二块同型号开发板、不同固件编译配置、时钟设置或供电条件扩展到跨条件实验。论文表述应明确区分“单设备实测”和“跨设备验证”。

### 风险三：普通示波器采样能力不足

优先使用学校已有设备或共享 ChipWhisperer。ChipWhisperer-Nano 内置 STM32F030 目标并提供基础功耗采集能力，适合快速入门，但它不适合作为多设备实验的唯一平台；需要跨设备时，应使用两块外部目标板配合合适的采集设备。

### 风险四：真实数据量不足以训练复杂模型

先采用较小模型和固定目标字节，减少输入窗口和训练成本；把研究重点放在数据质量、跨设备差异和指标分析上，而不是盲目增加模型规模。

## 十一、设备配置建议

### 最低可行配置

- 1 台共享的 ChipWhisperer-Nano；
- 1 台运行 Python 的电脑；
- 自编 AES-128 固件和串口控制程序；
- 用于保存和管理轨迹的硬盘空间。

这套配置只承担单设备真实攻击验证，不强制承担跨设备迁移。

### 更稳妥的共享设备配置

- 1 台 ChipWhisperer-Lite 或实验室已有等效采集设备；
- 2 至 3 块 Raspberry Pi Pico、STM32 或其他低成本目标板；
- 分流电阻、面包板、导线、稳定电源；
- 必要的同轴线、触发线和目标板连接线；
- 计算机和 GPU 环境。

ChipWhisperer-Lite 适合作为共享实验室设备，而不是每名学生单独购买。它可以降低模拟信号采集、增益和触发同步的工程难度，但课题的研究贡献仍应来自真实数据、跨设备分析和方法验证，而不是设备本身。
