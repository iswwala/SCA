# 面向跨设备建模侧信道分析的无监督域适应与负迁移抑制研究

## 一、课题简介

密码算法通常通过数学设计保证其计算安全性，但算法在真实芯片、微控制器或嵌入式设备上运行时，可能通过功耗、电磁辐射、执行时间等物理信息间接泄露中间数据。攻击者可以利用这些泄露信息，推断 AES 等密码算法使用的秘密密钥，这类攻击被称为侧信道分析。

建模侧信道攻击是一种重要的侧信道攻击方法。攻击者首先使用一台可控设备采集带有标签的功耗或电磁轨迹，训练机器学习模型学习“轨迹波形—密码中间值”的关系；之后将模型应用到目标设备的未标记轨迹上，并通过密钥候选排序逐步恢复密钥。

理想情况下，建模设备和目标设备具有相同的芯片、相同的采集环境和相同的测量位置。但在实际场景中，攻击者往往只能获得与目标设备相似而非完全相同的设备。芯片个体差异、探针位置、采样时钟、噪声、温度和供电条件都会使两个设备产生不同的轨迹分布。于是，模型可能在建模设备上表现很好，在目标设备上却无法正确识别泄露信息。

本课题研究的核心问题是：

> 在目标设备缺少标签的情况下，如何利用目标设备的无标签轨迹，减小源设备与目标设备之间的分布差异，同时保持密码中间值类别的判别边界，从而提高密钥恢复效率？

## 二、与当前研究方向的衔接提示

本课题可以作为当前 CDAN-SCA 研究中的一个独立实验与方法支线。学生不需要重新承担整个项目，而是围绕下面的主问题完成一组可回收的研究工作：

> 在 256 类侧信道分类中，普通的全局域对齐是否会造成负迁移？加入类别结构、预测置信度或其他侧信道信息后，能否更稳定地改善目标设备上的密钥恢复？

建议将工作逐步收敛为四个层次：

1. **统一比较**：在相同数据划分、训练预算和 GE 评价下，比较仅源域训练、全局域适应和类别感知域适应等路径；
2. **机制检验**：观察域判别准确率、目标预测熵、类间分离和 GE 是否同步变化，重点找出“域差异变小但密钥排名变差”的情况；
3. **轻量扩展**：针对一个明确问题加入小规模改进，例如目标样本置信度筛选、类别结构保持、特征统计约束或时序偏移处理；
4. **结果回收**：将统一训练器、逐 seed 结果、消融图表和失败案例整理为当前论文的主实验、机制分析或补充实验。

这里的四个层次是研究推进顺序，不是限定算法。小组可以根据预实验结果决定采用哪一种条件信息或约束，但必须说明它与“保持侧信道类别结构、减少负迁移”之间的关系。

### 预期对当前项目的直接帮助

- 补齐多种域适应路径的公平对比；
- 为“全局边缘对齐可能损害 256 类侧信道判别边界”提供支持或否定证据；
- 验证预测熵、类别结构或其他约束是否值得加入 CDAN-SCA；
- 产生可直接用于论文的 GE 曲线、消融表、机制图和失败分析；
- 沉淀统一的 source-target 训练接口和真实攻击指标评价流程。

如果小组无法完成轻量扩展，仍应优先保证统一比较和机制检验。这两部分本身就能为当前项目判断 CDAN-SCA 的研究假设是否成立提供有效证据。

## 三、使用的数据集

本课题建议采用“受控域偏移数据 + 真实多设备数据”的两级数据方案。

### 1. 主数据集：ASCAD 系列

ASCAD 用于建立统一的 256 类 profiling SCA 任务，并完成方法开发、训练接口调试和受控域偏移实验。建议使用：

- **ASCAD fixed-key 原始版本**：作为源域建模和基础攻击评估数据；
- **ASCAD desync50**：模拟中等程度的时序去同步；
- **ASCAD desync100**：模拟更强的时序去同步；
- **ASCAD Gaussian Noise 或 Clock Jitter 版本**：用于检验噪声和采样扰动下的迁移能力。

这些数据通常来源于同一类公开 ASCAD 轨迹的受控变换，因此应称为**受控域偏移实验**，不能直接等同于真实的跨芯片或跨设备实验。它们适合用于固定变量、比较方法和定位负迁移机制。

### 2. 真实跨设备数据：CDPA 数据集

在方法经过 ASCAD 受控实验筛选后，建议使用 CDPA 公开数据进行真实跨设备验证。该数据集包含：

- **XMEGA**：8 个 XMEGA 芯片上的未防护软件 AES-128 轨迹；
- **SAKURA-AES**：3 块 SAKURA-G 板卡上的未防护硬件 AES-128 轨迹；
- **CHES CTF 2018**：不同设备上的掩码软件 AES-128 轨迹；
- **XMEGA-EM**：不同近场探针位置采集的电磁轨迹，用于研究测量位置变化。

这些数据更适合回答“方法能否跨越真实设备或采集条件差异”的问题。建议采用单源到单目标、多源到单目标或留一设备测试，目标域训练阶段只使用无标签轨迹，目标标签只用于最终攻击评价。

### 3. 推荐使用顺序

1. 使用 ASCAD 原始版本完成源域监督建模和 GE 评估；
2. 使用 desync50、desync100 和噪声版本完成受控域偏移筛选；
3. 选择表现稳定的技术路径，在 XMEGA 或 SAKURA-AES 上进行真实跨设备验证；
4. 若数据和算力允许，再加入 CHES CTF 2018 或 XMEGA-EM 作为更强泛化检验。

### 4. 数据边界

- ASCAD 的去同步、噪声和时钟扰动版本是**模拟或受控偏移**；
- XMEGA、SAKURA-AES、CHES CTF 2018 和 XMEGA-EM 才能支撑更强的真实跨设备或跨采集条件表述；
- 不同数据集的标签定义、目标密钥字节、轨迹长度和文件格式可能不同，必须在实验开始前分别建立数据契约；
- 不应把不同数据集的准确率或 GE 直接混合平均，跨数据集结论应使用各自内部公平对比。

## 四、研究背景与现状

### 1. 深度学习已经成为建模侧信道分析的重要工具

公开的 ASCAD 数据库推动了深度学习侧信道分析的标准化研究。该类数据通常把一条功耗或电磁轨迹表示为固定长度的数值序列，并将某个 AES 中间值作为 256 类分类标签。模型训练完成后，再根据每条攻击轨迹对 256 个密钥候选的概率进行累积，计算真实密钥的猜测熵、密钥排名和成功率。

与传统模板攻击、相关功耗分析相比，卷积神经网络能够自动学习时间窗口、非线性泄露关系和较复杂的噪声模式，因此被广泛用于 profiling SCA。现有研究和公开基准已经证明，深度模型能够在同设备或相近数据分布上实现有效攻击。

### 2. 跨设备问题是深度侧信道分析走向实际应用的重要障碍

早期深度学习侧信道分析工作通常在同一设备或高度相似的数据分布上训练和测试。跨设备研究表明，不同设备之间的变化可能大于不同密钥类别之间的变化，导致模型学习到设备特有的波形特征，而不是稳定的密钥相关泄露特征。

已有跨设备研究探索过多设备联合训练、特征变换、降维、噪声处理和模型可迁移性等路线。这些工作说明跨设备攻击是一个真实且困难的问题，但仍存在以下不足：

- 不同工作使用的数据集、设备数量、预处理方式和评价指标并不完全统一；
- 许多方法需要多个带标签的建模设备，或需要对目标设备进行有标签微调；
- 对“目标域无标签”条件下的跨设备适应研究仍不充分；
- 普通分类准确率不能完整反映密钥恢复效果；
- 域差异降低并不必然意味着真实密钥排名改善。

### 3. 无监督域适应提供了一个可研究的方向

无监督域适应通常假设源域有标签、目标域没有标签。域适应模型希望学习既能完成源域分类、又不依赖于域身份的特征。DANN 通过梯度反转层训练域判别器，使特征提取器尽量难以区分源域和目标域；这种方法为无标签目标域迁移提供了通用框架。

然而，侧信道分析通常是高度多模态的分类问题。若只进行全局特征分布对齐，可能把不同密钥类别的特征错误地拉近，造成类别混淆或负迁移。CDAN 等条件域适应方法尝试将分类预测信息加入域判别过程，以处理多模态分类分布，但这些方法如何适配侧信道波形、如何与密钥排名指标对应、在何种设备偏移下有效，仍需要专门研究。

## 五、拟解决的科学问题

本课题可以围绕以下问题展开：

1. 源设备与目标设备之间的哪些变化最容易导致建模侧信道攻击失败？
2. 全局分布对齐、类别条件对齐、统计特征对齐或其他路径，在侧信道分析中各自解决什么问题？
3. 降低域判别准确率是否一定能够改善猜测熵和密钥排名？
4. 目标域预测置信度是否能够可靠地反映伪标签质量？
5. 域适应方法在什么样的偏移条件下有效，什么样的条件下会发生负迁移？
6. 是否能够设计一种更适合 256 类侧信道分类的跨域训练路径？

## 六、研究内容

本课题不预设唯一算法，具体方法由小组在调研和预实验后确定。研究内容可以包括以下几个层次。

### 1. 建立跨设备侧信道分析问题定义

- 明确源域、目标域、建模阶段和攻击阶段；
- 说明目标域哪些信息可以用于训练，哪些信息只能用于最终评估；
- 明确中间值标签、密钥候选、目标字节和攻击轨迹的关系；
- 统一猜测熵、密钥排名、成功率和达到密钥恢复所需轨迹数的定义；
- 分析分类准确率与实际密钥恢复指标的区别。

### 2. 构建具有逻辑差异的技术路径

小组可以从以下方向中选择若干条进行比较：

- 仅使用源域标签的监督建模；
- 基于全局特征分布的域适应；
- 基于类别或预测结果的条件域适应；
- 基于统计距离或特征矩的分布匹配；
- 基于伪标签、置信度或一致性的目标域利用；
- 基于数据增强、去同步校正或波形变换的迁移；
- 多源设备联合建模或留一设备泛化；
- 其他能够解释源域和目标域关系的训练策略。

不同路径不应只是更换模型名称，而应回答不同的研究假设。例如，一种方法试图对齐整体分布，另一种方法试图保持类别结构，第三种方法可能通过数据变换减小时序差异。

### 3. 研究负迁移及其成因

重点分析以下现象：

- 域判别器变得难以区分两个域，但 GE 变差；
- 目标分类准确率提高，但密钥排名没有改善；
- 模型在目标域产生大量低熵但错误的预测；
- 某种方法只在轻度偏移下有效，在强偏移下失效；
- 适应损失过大时，源域类别边界被破坏；
- 不同随机种子得到相反结论。

### 4. 设计验证和消融实验

建议至少包含：

- 不同方法之间的公平比较；
- 去掉关键组件后的消融；
- 目标域无标签样本数量变化；
- 域偏移强度变化；
- 至少三个随机种子；
- 分类指标与攻击指标的对照；
- 特征空间、域判别和预测置信度分析。

如果条件允许，还可以增加不同设备、不同实现或多源域设置，以检验方法是否只对单一数据配对有效。

## 七、三人小组分工建议

### 第一人：数据与实验协议

- 侧信道数据和元数据整理；
- 源域、目标域及评估集划分；
- 域偏移设置和数据质量检查；
- 攻击指标和结果格式定义；
- 可复现配置与实验记录。

### 第二人：模型与训练方法

- 设计和实现候选跨域训练路径；
- 统一模型、损失、优化器和训练接口；
- 完成主方法和关键消融。

### 第三人：评估与机制分析

- 计算 GE、key rank、SR 和 NTGE；
- 分析特征分布、类间分离和域判别结果；
- 研究负迁移案例和适用边界；
- 绘制论文图表并整理结论。

## 八、预期成果

- 至少三条技术路径的公平对比；
- 一条具有明确动机的改进路径；
- GE、key rank、SR、NTGE 和辅助诊断指标；
- 消融、敏感性和多 seed 结果；
- 负迁移案例和方法适用边界；
- 可复现实验代码、配置、日志和图表。

### （可用于后续论文的成果）

- 主实验和 baseline 对比；
- 域适应方法或训练路径的扩展；
- 条件对齐、置信度或类别结构的机制分析；
- 负迁移和失败边界章节；
- 统一评价协议和补充实验材料。

## 九、课题难点与风险

- 真实目标域数据和多设备数据可能不容易获得；
- 训练环境、GPU 和数据预处理会影响实验可重复性；
- 域适应方法可能对超参数敏感；
- 准确率、域判别准确率和 GE 可能出现不一致；
- 单次实验的提升不能直接说明方法有效；
- 如果目标域偏移改变了泄露语义，仅靠分布对齐可能无法解决问题。

因此，课题不应把“最终一定优于 baseline”作为前提。严谨的失败分析和适用条件同样可以构成有价值的研究结果。
